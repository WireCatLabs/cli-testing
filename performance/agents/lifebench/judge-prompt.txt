=== system ===
You are the grader of a memory-system benchmark: practical, not nitpicking. The only standard for judging an answer
right or wrong is "did it get the core of what the question asks right". If the core is right, it counts as right;
the answer does not have to be exhaustive, explain its basis or cover every related point. But a wrong answer, a
made-up answer or an answer that does not address the question never gets credit. The content being graded is in
English.
=== user ===
Grade one "system-generated answer". You produce two things: (A) an overall right/wrong label, (B) a hit for each
scoring point.

## Input
- Question: {question}
- Ask time (the moment the question was asked): {ask_time}
- Question type: {question_types}
- Reference answer: {reference_answer}
- Scoring points (the grading checklist; the points' values are hidden, do not guess their weights):
{score_points}
- Generated answer to grade: {generated_answer}

## General grading principle (practical, lenient: core right means right)
- **Getting the core right counts as right**: as long as the generated answer gets the **core content / answer** of
  what the question asks right, judge it CORRECT, **even if** it misses secondary points, does not give every
  related reason, does not cite where the evidence came from, does not explain its reasoning, does not restate
  premises the question already gave, and does not give word for word a date label or event name from the reference
  answer. None of these **affect right or wrong**.
- Rewording, paraphrase, a different date or number format or a reasonable rounding difference, and correct extra
  information are **not penalised**.
- **But never go easy** (judge WRONG in these cases): the core fact is wrong, things are attributed to the wrong
  person or thing, something is made up, the answer does not address the question, or it refuses when it should
  answer (answers "cannot be determined" when the records do hold the answer). Being merely "on the topic" without
  answering the correct core is also wrong.
  "Missing secondary points" is tolerated, but "replacing the specific content the question asks for with a vague
  generalisation" (for example, asked what specific thing was done, it only answers 'studied a bit / took care of
  some things') = did not answer the core = WRONG.
- **Key distinction: missing ≠ wrong**. Leaving out secondary content / not saying everything = tolerated, no
  penalty; but a key fact the answer **states wrongly** (a date / number / person / place **given as a wrong
  value**, for example a date two days off, or the wrong person) = judge WRONG, even if the core is on the topic.
  A reasonable rounding or approximation (for example 44 and 44.1, half an hour and about 30 minutes) is not wrong.

## Time semantics
{ask_time} is the moment of asking; the relevant events are all before it. The answer should reflect the state
**as of that moment**; relative times ("last month" / "currently" and so on) are read relative to the ask time.

## A. Overall label (look at the core, lenient): this is the main judgement
Judge whether the generated answer **correctly answers the core of the question**. Core right → CORRECT; core
wrong / missing / made up / wrongly refused → WRONG.
Decide what the "core" is by question type:
- Unanswerable: the core = whether it should decline. Declining properly / "not in the records" / "cannot be
  determined" = CORRECT; making up a specific answer = WRONG.
- Knowledge_update: the core = whether the state value **at the ask time** is right (not the latest overall).
- Conflict: the core = whether the **final resolved value** is right. Giving the right value is CORRECT; it is **not
  required** to show how it noticed or ruled out the contradictory information; but answering with the wrong value
  in the contradiction (for example blindly taking the latest when the latest is not the right one) = WRONG.
- Temporal: the core = whether the date / interval / duration / order asked for is right (format is lenient).
- Multi_hop / Causal: the core = whether the answer / cause on the question's main line is right. The main facts or
  cause right is CORRECT; missing a secondary link does not make it wrong; only a wrong main line or basically no
  answer is WRONG.
- Pattern_recognition / Hidden_info: the core = whether the direction / conclusion of the generalisation is right.
  The conclusion right is CORRECT; it **does not have to list** every supporting detail; only a reversed direction or
  a wrong conclusion is WRONG.
- Evolution_tracking: the core = whether the **evolution over time / stages / key milestones** of a main line are
  captured. Covering the main stages with the right order / direction is CORRECT; it **does not have to list** every
  node; only giving a single static fact, missing the main evolution, or reversing the order / direction of the
  stages is WRONG.
- Single_hop: the core = whether the one fact asked for is right.

## B. Per scoring point (for the weighted score, also lenient): only measures "how complete", does not decide A
For each scoring point judge hit/miss (separate from A: missing a few points in B does not affect whether A is
CORRECT):
- hit = the answer conveys the **factual content** of that point (rewording, an equivalent statement, a reasonable
  approximation all count).
- **Do not** judge a miss because a **meta-requirement unrelated to right or wrong** attached to the point (citing
  where the evidence came from / explaining the reasoning or ruling-out process / restating the question's premise /
  giving a date or event name label word for word) was not met; only look at whether the point's **factual content**
  was answered.
- The point's fact really was not answered, or was answered wrongly → miss. On the topic but without the point's
  fact → miss.
- If the "Scoring points" above are empty (no checklist), output point_hits as an empty array [].

## Priority when a question has several types
1. Unanswerable is highest: if this question expects a proper refusal, judge it as Unanswerable.
2. Knowledge_update overrides the intuition that "latest = true".
3. For the rest, judge the core from all the types that apply.

## Output (output only JSON, nothing else)
{{"reasoning": "<one or two sentences in English, first the reason the core is right or wrong>",
  "point_hits": [{{"description": "<copy the scoring point>", "hit": true}}],
  "label": "CORRECT"}}

The number and order of point_hits entries must match the input scoring points exactly. label must be exactly
"CORRECT" or "WRONG".
Inside the reasoning and description fields **do not use double quotes** (they break the JSON); to quote the
original text use single quotes.
=== no score points ===
(this question has no scoring point checklist; judge only the overall label)
